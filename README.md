# java-racingcar-precourse

**기능** 
- 자동차 이름 입력, 잘못된 값일 경우 IllegalArgumentException
- 시행 횟수 입력, 잘못된 값일 경우 예외 발생
- 자동차 대회 시행 
- 시행 결과 출력 

<br>

## 신경 쓴 점 

- 1주차 과제의 피드백을 수용했습니다.
    - 컨밴션 지키기
    - 불필요한 파일 포함하지 않기
    - 절차 지향이 아닌 객체 지향적 프로그래밍 하기
    - 메서드 이름 명확하게 짓기
    - 단일 책임 원칙 준수
    - 메인이 아닌 내 이름 브렌치 파기
    - 캡슐화에 신경 쓰기(정적 팩터리 메서드 적용) 

- mvc 모델을 적용했습니다.
  - getter, setter 사용하지 않기
  - 도메인에 비즈니스 로직을 넣기
  - 컨트롤러는 흐름을 제어하고 메인에 노출되기
 
<br>

## 생각을 나누고 싶은 점 

- 상속보다는 합성을 늘리라는 원칙에 의해 자동차 대회 클래스가 자동차 클래스를 갖고 있게 작성했습니다.
  프로그램 구조와 요구사항, 미래의 수정 가능성을 따져보고 인터페이스는 도입하지 않았습니다.
  인터페이스를 사용하신 분들의 코드와 의도가 궁금합니다.

- 단일 책임 원칙을 준수하려 노력했지만, 단일 책임이란 무엇인지에 대해 고민할 필요성을 느꼈습니다.

- 클래스들의 상호작용과 흐름 제어를 컨트롤러에서 담당하면서, 예외 발생 코드도 컨트롤러가 갖게 되었는데
  더 깔끔한 처리는 없었을지 의견 들어보고 싶습니다.

- 풍부한 도메인 모델을 적용하기 위해 비즈니스 로직을 모델이 갖게 구현했습니다. 서비스의 책임은 어디까지일지
 의견 들어 보고 싶습니다.
